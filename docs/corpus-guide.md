# 코퍼스 확보 가이드

이 문서는 연구 코퍼스의 후보를 찾고 권리와 위험을 검토하는 절차를
정의한다. Phase 0의 `research/corpus-sources.yaml`은 후보 목록일 뿐, 다운로드나
수집 승인을 뜻하지 않는다. 무료 열람 가능성과 재배포 허락도 같은 뜻이 아니다.

각 후보의 `estimated_size`에는 확인한 카탈로그 건수처럼 측정 단위와 근거가 있는
규모를 적는다. 고정 스냅숏이나 원문을 확보하지 않아 측정할 수 없으면 추정치를
만들지 말고, 무엇을 아직 측정하지 않았는지와 그 이유를 명시한다. 실제 수집을
승인할 때는 고정 버전에서 파일·레코드·문장 등 적절한 단위를 다시 측정한다.

## 승인 단계

1. 제공기관이 직접 관리하는 공식 랜딩 페이지를 찾는다.
2. 저작권 표시, 공공 라이선스 식별자, 정확한 이용약관 URL, `robots.txt` 또는
   API 호출 제한, 확인일을 기록한다. 검색 결과 요약이나 제3자 미러는 근거로
   쓰지 않는다.
3. 원문 재배포 권리와 번역·정규화·텍스트 추출 같은 2차적 저작물 작성 권리를
   서로 독립적으로 분류한다. 파일 안의 제3자 표준, 도면, 사진, 코드 예제에는
   별도 조건이 있을 수 있으므로 문서 전체의 허락으로 일반화하지 않는다.
4. 다운로드 전에 공개된 샘플과 메타데이터에서 개인정보, 서명, 연락처,
   개인을 식별할 수 있는 정비 기록, 보안에 민감한 절차를 점검한다.
5. 원문을 받기 전에 메타데이터 수집만 먼저 승인한다. 이때도 제공기관, 제목,
   버전, URL, 권리 판단과 제외 범위를 검토한다.
6. 승인된 원본은 Git 밖의 `research/sources/`에 로컬 연구용으로만 둔다. 이
   디렉터리의 README 외 파일은 저장소에 추적하지 않는다.
7. 라이선스가 변형을 명시적으로 허용할 때만 파싱·번역·정규화한 파생 텍스트를
   만든다. 조건이 자료 유형별로 다르면 허용된 부분만 분리한다.
8. 실제 확보 단계에서는 별도 코퍼스 매니페스트에 추출 명령, 원본과 결과물의
   체크섬, 문자 인코딩과 정규화 절차, 제외 항목과 이유를 기록한다.

`allowed`는 현재 공식 조건이 저장소에서 계획한 이용을 직접 허용할 때만 쓴다.
원문은 허용하지만 변형이 불명확하면 두 필드의 값이 달라야 한다. 페이지에
접근하지 못했거나 표시가 충돌하면 `unknown`, `metadata-only`, 또는
`permission-required`를 선택하고 승인하지 않는다. 공공데이터포털 항목은 각
항목의 현재 표시를 따로 확인하고, 공공누리는 해당 게시물에 붙은 유형만
적용한다. 행정규칙 본문과 첨부된 민간 표준·도면도 별개 자료로 취급한다.

## 거절 및 중단 규칙

다음 후보는 수집을 거절하거나 권리자 확인 때까지 중단한다.

- 제공자와 생성 경로를 확인할 수 없거나 제3자 미러만 있는 자료
- URL에 계정 자격증명, API 키, 토큰, 서명된 다운로드 매개변수가 있는 자료
- 개인 이름, 서명, 연락처 또는 개인을 식별할 수 있는 정비·의료 기록이 포함된
  자료(안전하게 분리·비식별화할 명시적 승인과 절차가 없는 경우)
- 약관, `robots.txt`, API 정책이 자동 접근·대량 다운로드·재배포를 금지하는
  자료
- 제3자 저작물의 권리 범위를 분리할 수 없는 자료
- 라이선스 표시가 서로 충돌하거나 적용 버전을 확정할 수 없는 자료

자동 접근이 허용되어도 요청 속도, 인증, 일일 한도와 사용 중단 조건을 지킨다.
인증키가 필요한 API의 키는 URL이나 매니페스트에 기록하지 않는다. 권리 또는
개인정보 판단이 바뀌면 확보를 즉시 멈추고 레지스트리부터 갱신한다.

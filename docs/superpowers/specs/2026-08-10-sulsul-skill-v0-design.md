# sulsul 스킬 v0 설계

## 1. 목적

sulsul(술술)은 KSTL 규칙 후보를 첫 실사용자에게 전달하는 에이전트 스킬이다.
한국어 개발자 문서를 KSTL 규칙 후보 10개에 대조해 고치고, 어떤 규칙이 실전에서
걸리는지 기록한다. 이 기록은 Phase 1 규칙 검증의 파일럿 데이터가 된다.

v0은 표준 승인이 아니다. 규칙은 모두 `candidate`이며 스킬은 그 사실을
사용자에게 표시한다.

## 2. 브레인스토밍 확정 결정

2026-08-10 브레인스토밍에서 다음을 확정했다.

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| 첫 쐐기 | 한국어 개발자 문서(README, 가이드, API 문서) | Claude Code 스킬의 실사용자가 개발자다. 피드백 루프가 가장 빠르다. |
| 기본 동작 | 그냥 고쳐줌(재작성). 진단 리포트는 기본 출력이 아니다. | caveman(97k★)이 증명한 zero-ceremony UX. 이유 설명은 표준 개발자의 필요이지 사용자의 필요가 아니다. |
| 위치 | kstl 모노레포 `skill/sulsul/` | 규칙 데이터와 스킬의 단일 원천 유지. |
| 이름 | sulsul(술술) | 결과 약속형 이름. wait-what은 mattpocock/skills가 이미 사용한다. |

| 어휘 | v0 제외 | `entries.yaml`은 형식 예시 5개뿐이다. 포함하면 승인 어휘로 오해된다. |
| stats | v0 포함, 원문 비기록 | 사용자에게는 공유 가능한 수치, 프로젝트에는 규칙 검증 데이터. |
| 수치 정책 | v0은 카운트만. 합성 지수 금지 | 아래 7절. |

## 3. 성공 기준

v0은 다음 조건을 모두 만족할 때 완료된다.

1. `/plugin install`로 설치할 수 있고, 자연어 호출("이 문서 술술하게 해줘")이
   동작한다.
2. `skill/sulsul/` 산출물이 `scripts/generate_skill.py` 재실행 결과와 byte
   단위로 일치하고, 이를 테스트가 강제한다.
3. 규칙 10개가 모두 스킬에 반영되고, `automation: human` 규칙 3개는 질문
   게이트로 분류된다.
4. kstl 저장소 자체 문서에 sulsul을 실행한 dogfood 기록이 남아 있다(걸린
   문장, 오탐 여부).
5. 외부 공개 한국어 OSS 문서 2편 이상에 실행한 규칙 히트 통계가 기록되어
   있다. 원문은 재배포하지 않는다.

## 4. 범위

### 포함

- `skill/sulsul/SKILL.md`와 `references/rules.md` 생성기
- Claude Code 플러그인 매니페스트(`/plugin install sulsul@kstl`)
- stats 기록·조회 규약(로컬 파일, 규칙 ID와 수치만)
- 생성물 동기화·계약 테스트

### 제외

- 결정론적 규칙 엔진, CLI, MCP, LSP(Phase 2)
- 어휘 통제(승인 어휘 사전이 없다)
- 합성 가독성 지수(7절의 정책에 따라 Phase 3)
- 자동 켜짐(SessionStart 훅) — caveman의 최다 불만 사항이다
- Node·Python 런타임 의존 — v0은 순수 스킬 문서다
- 마켓플레이스 외부 배포 미러(별도 레포, npm 등)

## 5. 인터페이스

```text
설치    /plugin marketplace add domuk-k/kstl
        /plugin install sulsul@kstl
호출    /sulsul [파일|텍스트]  또는  자연어("이 문서 술술하게 해줘")
기본    고친 결과 + 한 줄 요약: SYN-001 ×2 · TER-001 ×1 · 나머지 이미 좋음
검사만  "검사만 해줘" → 고치지 않고 걸린 문장 목록(리뷰용)
이유    "왜 바꿨어?" → 그때만 규칙 ID·근거·연구 출처 설명
stats   "통계 보여줘" → 누적 고친 문장 수, 최다 발동 규칙, 공유용 한 줄
게이트  의미가 두 갈래인 문장은 추측하지 않고 한 줄로 묻는다
```

플래그는 없다. 범위 조정("이 문단만"), 강도 조정은 자연어로 받는다.

보존 보장: 코드 블록, 셸 명령, URL, 숫자와 단위, 오류 문자열은 byte 단위로
보존한다. 재작성은 각 규칙의 `example_invariants`가 정의하는 의미
불변식(행위자, 대상, 조건, 순서, 양태)을 지킨다.

선례에서 채택한 것: 자연어 우선·플래그 최소(im-not-ai), 조기 종료 신뢰
메시지 "이미 잘 읽힙니다 — N곳만 고침"(im-not-ai), byte-exact 보존
명시(caveman), 후속 조정 대화(im-not-ai `/humanize-redo`). 회피한 것: 자동
켜짐, 매니페스트 버전 드리프트, `_workspace/` 잔여 디렉터리, 공격적 자연어
트리거.

## 6. 아키텍처

```text
standard/rules/candidates.yaml    원천(무변경)
scripts/generate_skill.py         결정론적 생성기(신규)
skill/sulsul/SKILL.md             생성됨: 트리거, 워크플로, 보존 보장, 규칙 요약
skill/sulsul/references/rules.md  생성됨: 규칙 16개 상세(예문 쌍, 재작성 지침, 예외)
.claude-plugin/                   플러그인·마켓플레이스 매니페스트
tests/test_skill_sync.py          동기화·계약 테스트(신규)
```

생성 규칙:

- 같은 입력에서 byte 동일 출력을 낸다. 타임스탬프를 넣지 않는다.
- `automation: deterministic | heuristic` 규칙 7개는 "고침 규칙"으로,
  `automation: human` 규칙 3개(KSTL-SYN-002, KSTL-REF-001, KSTL-SAF-001)는
  "질문 게이트 규칙"으로 렌더링한다. 질문 게이트 규칙은 조용히 고치지 않는다.
- 각 규칙 항목은 ID, 제목, 한 줄 지침(`rewrite_guidance` 요약), 예문 쌍,
  예외를 담는다. `purpose`의 연구 근거는 "이유" 모드 응답을 위해
  `references/rules.md`에만 담는다.
- SKILL.md 머리에 "KSTL 규칙은 candidate 단계"임과 표준 저장소 링크를
  명시한다.

stats 규약:

- 실행마다 `~/.claude/sulsul/stats.jsonl`에 한 줄 추가: 날짜, 검사 문장 수,
  고친 문장 수, 규칙별 히트 수. 문서 내용, 파일명, 경로는 기록하지 않는다.
- 조회 시 누적 합계와 공유용 한 줄("sulsul이 두 번 읽게 만드는 문장 N개를
  없앴습니다")을 출력한다.
- 집계 방식은 SKILL.md에 명시한다(caveman-stats의 2배 과대집계 이슈 회피).
- 삭제는 파일 삭제로 끝난다. 외부 전송은 없다.

## 7. 수치 정책

2026-08-10 조사 결과, 한국어 가독성 지표는 학술(조용구 2016 이독성 공식,
서혁 외 2013, 이보미 2020, 최소영 외 2024)과 상용(KReaD, 낱말 LQ, KICE
연구) 모두 교육 텍스트로만 검증되었고, 기술문서 대상으로 검증된 지표는
없다. 이 공백은 KSTL의 기회이지만 v0의 몫이 아니다.

- v0은 사실 카운트만 보고한다: 검사 문장 수, 고친 문장 수, 규칙별 히트.
- 평균 문장 길이 같은 서술 변수는 보여줄 수 있으나 "지수", "점수", "등급"
  이라는 이름을 붙이지 않는다.
- 검증되지 않은 합성 점수를 만들지 않는다. 기술문서용 지표 개발과 검증은
  Phase 3 평가 설계에서 다룬다. 조사에서 확인한 지표 선례는
  [`docs/HANDOFF.md`](../../HANDOFF.md)의 조사 단서 목록에 있다.

## 8. 테스트

기존 스위트에 추가한다.

1. 생성기 재실행 결과가 커밋된 `skill/sulsul/` 산출물과 일치한다.
2. SKILL.md에 규칙 ID 10개가 모두 존재한다.
3. `automation: human` 규칙이 모두 질문 게이트 섹션에 있고, 고침 규칙
   섹션에 없다.
4. 플러그인 매니페스트의 스킬 이름·버전이 SKILL.md frontmatter와 일치한다.
5. SKILL.md에 candidate 단계 고지와 저장소 링크가 있다.
6. stats 규약 문구(원문 비기록, 로컬 전용)가 SKILL.md에 있다.

## 9. 개정 이력

2026-08-10 오피스아워(빌더 모드, Codex 교차 검증, 적대적 리뷰 2라운드 9/10)에서
다음을 확정해 구현 계획에 반영했다. 근거: 구조 규칙 10개는 어휘·표현 층위의
번역투·AI투를 잡지 못하는데, 첫 사용자 페인은 정확히 그 층위다.

- **규칙 16개 체제**: 번역투·AI투 표현 후보 규칙 KSTL-EXP-001~006 추가
  (서지 선행 작성, 필수 14필드, automation 판정 규칙 포함 — 계획 Task 0).
- **쓰기 모드**: 사후 교정에 더해, 에이전트가 한국어 문서를 작성할 때
  규칙을 사전 적용하는 모드("KSTL로 써줘")를 SKILL.md에 생성한다.
  트리거 문구는 frontmatter description에 포함한다.
- **3자 비교 파일럿**: dogfood를 vanilla Claude / writing-for-agents /
  sulsul 블라인드 비교(평가자 3명 이상, 원문 비저장·익명 통계만)로
  격상한다. 3절 성공 기준 4는 이 형식으로 대체된다.

## 10. 리스크와 열린 질문

- 규칙 후보의 예문은 절차문 중심이다. 개발자 문서(README 산문)에서 오탐
  빈도가 높으면 dogfood 기록을 근거로 규칙 표현을 조정한다. 조정은
  `candidates.yaml`에서만 한다.
- 자연어 트리거 문구("술술하게")의 오발동 빈도는 dogfood에서 관찰한다.
  caveman의 "normal mode" 오발동 선례가 있으므로 트리거는 보수적으로
  시작한다.
- stats 파일 위치(`~/.claude/sulsul/`)는 에이전트 환경에 따라 쓰기 권한이
  다를 수 있다. 구현에서 실패 시 조용히 건너뛰고 보고만 생략한다.
- 마켓플레이스 등록명(`sulsul@kstl`)은 저장소 공개 설정과 함께 구현 시점에
  확정한다.

3절 성공 기준 1~5를 아래 방법으로 검증했다.

1. **설치·자연어 트리거** — `.claude-plugin/plugin.json`,
   `.claude-plugin/marketplace.json`에 sulsul 플러그인 매니페스트가 있고,
   `skill/sulsul/SKILL.md` frontmatter의 `description`에 "술술하게 해줘",
   "이 문서 검사만 해줘", "KSTL로 써줘", "술술 문체로 써줘" 자연어 트리거가
   있다. **달성(정적 확인: 매니페스트 스키마·트리거 문구 존재 확인. 실제
   설치·자연어 호출 리허설은 미실행 — 머지 후 수행 예정)**.
2. **생성물 byte 동일** — `uv run python scripts/generate_skill.py --check`
   종료 코드 0. **달성**.
3. **규칙 반영과 게이트 분류** — `uv run pytest tests/test_skill_sync.py -q`
   11 passed(게이트 분류 테스트 포함). SKILL.md의 "고침 규칙" 표 13개(질문
   게이트 3개 제외)와 "질문 게이트 규칙" 표 3개(KSTL-SYN-002,
   KSTL-REF-001, KSTL-SAF-001)로 16개 규칙 전부가 반영되어 있다. **달성**
   (원래 기준의 "규칙 10개"는 9절 개정으로 16개로 확장됨 — 아래 개정 이력
   항목 참고).
4. **내부 dogfood 기록** — `docs/pilot/2026-08-sulsul-dogfood.md`에 판정
   표(2건: 정탐 1, 오탐 1)와 집계(검사 문장 59개, 규칙별 히트, 오탐 원인
   메모)가 채워져 있다. **달성**. 단, 9절 개정에 따라 이 항목은 3자 비교
   파일럿으로 격상되었고, 그 인간 평가는 아직 실행되지 않았다(아래
   "미달/대기 항목" 참고).
5. **외부 문서 통계** — `docs/pilot/2026-08-sulsul-external.md`에 공개
   한국어 OSS 문서 2편(Kubernetes 공식 문서 한국어판, React 공식 문서
   한국어판)의 판정 방법·문장 수(82, 61)·규칙별 히트 통계·종합 관찰이
   기록되어 있다. 원문은 재배포하지 않았다. **달성**.

9절 개정 이력에서 추가된 항목도 함께 확인했다.

- **규칙 16개 체제** — `uv run python -c "import yaml; ..."`로

- **쓰기 모드** — 생성된 `skill/sulsul/SKILL.md`에 "## 쓰기 모드" 절이

  절차가 기술되어 있다. frontmatter `description`에도 해당 트리거 문구가

- **3자 비교 프로토콜 문서화** — `docs/pilot/2026-08-sulsul-comparison.md`에

# KSTL Phase 0 연구 기반 설계

## 1. 목적

KSTL Phase 0은 한국어 통제 기술 언어를 설계하기 전에 필요한 검증 가능한 연구 기반을 만든다. 이 단계의 결과물은 단순한 자료 모음이 아니다. 이후 규칙 설계자와 도구 개발자가 각 주장, 설계 결정, 데이터의 출처와 사용 조건을 추적할 수 있는 작업 기반이다.

Phase 0에서는 체커를 구현하거나 KSTL 규칙을 표준으로 확정하지 않는다. 대신 다음 단계에서 검증할 규칙 후보와 기계 판독 형식을 정의한다.

## 2. 성공 기준

Phase 0은 다음 조건을 모두 만족할 때 완료된다.

1. ASD-STE100 핵심 주장마다 ASD 또는 STEMG 공식 출처가 연결돼 있다.
2. 한국어 통제언어 연구를 최소 3편 식별하고, 원문을 확보한 자료는 구조화된 형식으로 요약한다.
3. STE, Español Técnico Simplificado, Italiano Tecnico Semplificato, 프랑스어 통제 기술 언어의 공개적으로 확인 가능한 구조를 비교한다.
4. 코퍼스 후보마다 출처, 분야, 형식, 재배포 가능 여부, 개인정보 위험, 수집 방법을 기록한다.
5. 규칙과 어휘 데이터를 표현하는 JSON Schema 초안을 제공하고 유효성 검사를 통과시킨다.
6. 한국어 규칙 후보를 10개 이상 작성하고 각 후보의 근거, 예문, 자동 검사 가능성을 기록한다.
7. 제3자가 README에서 두 번 이하의 링크 이동으로 모든 Phase 0 산출물에 도달할 수 있다.

## 3. 범위

### 포함

- ASD-STE100 공식 웹 자료와 합법적으로 확보한 개인 연구용 사본의 분석 메모
- 한국어 통제언어 및 기술문서 관련 학술 자료의 서지정보와 자체 작성 요약
- 다른 언어권 통제 기술 언어의 공개 자료 비교
- 공개 한국어 기술문서 코퍼스 후보 조사
- 연구 증거의 검증 상태와 라이선스 상태 기록
- KSTL 규칙, 어휘, 코퍼스 메타데이터의 데이터 형식 초안
- 다음 단계에서 실험할 한국어 규칙 후보

### 제외

- ASD-STE100 원문 PDF 또는 통제 사전의 재배포
- 유료 서적과 논문의 본문 복제
- KSTL v1.0 표준 확정
- 자연어 처리 모델 학습
- CLI, MCP, LSP, 편집기 확장 구현
- 특정 산업의 비공개 문서 수집

## 4. 증거 정책

모든 연구 항목은 다음 검증 상태 중 하나를 갖는다.

| 상태 | 의미 | 사용할 수 있는 위치 |
|---|---|---|
| `verified` | 공식 기관 자료나 원문 학술 자료에서 직접 확인했다. | 요약, 설계 근거, 비교표 |
| `secondary` | 신뢰할 수 있는 2차 자료에서 확인했으나 원문을 아직 확인하지 못했다. | 조사 기록. 확정 설계 근거로는 사용하지 않는다. |
| `unverified` | 인수인계나 검색 단서만 있고 뒷받침 자료가 없다. | 조사 대기 목록에만 기록한다. |
| `contradicted` | 더 강한 출처가 해당 주장을 반박한다. | 정정 기록에 남기고 본문에서는 사용하지 않는다. |

각 출처에는 제목, 저자 또는 기관, 발행일, URL 또는 식별자, 접근일, 자료 유형, 검증 상태, 라이선스 또는 이용 조건, 관련 주장을 기록한다.

검색 결과 요약만으로 `verified` 상태를 부여하지 않는다. 공식 페이지 본문, 논문 원문, 기관 저장소의 서지 레코드처럼 독자가 다시 확인할 수 있는 자료를 사용한다.

```text
│   ├── bibliography.md
│   ├── claims.yaml
│   ├── korean-controlled-language.md

│   ├── rule.schema.json

│   └── corpus-source.schema.json

    ├── fixtures/
    └── test_schemas.py
```

파일의 책임은 다음과 같이 나눈다.

- `research/`는 외부 사실과 출처를 기록한다.
- `standard/`는 KSTL이 직접 정의할 규칙과 어휘만 담는다.
- `schemas/`는 기계 판독 계약을 정의한다.
- `docs/`는 사람이 수행하는 절차와 판단 기준을 설명한다.
- `tests/`는 데이터가 스키마와 프로젝트 불변 조건을 지키는지 검사한다.

외부 자료 원문은 `research/sources/`에 저장하지 않는다. 이 디렉터리에는 확보 방법과 로컬 보관 규칙만 문서화한다. 재배포가 명시적으로 허용된 자료를 향후 추가할 때도 출처별 이용 조건을 먼저 기록한다.

## 6. 데이터 설계

### 6.1 주장 레코드

`research/claims.yaml`의 각 항목은 다음 필드를 갖는다.

- `id`: 변경되지 않는 소문자 식별자
- `claim`: 검증할 수 있는 하나의 사실 문장
- `status`: `verified`, `secondary`, `unverified`, `contradicted` 중 하나
- `source_ids`: 참고문헌 항목 식별자 목록
- `checked_on`: 마지막 확인일
- `notes`: 충돌 또는 한계를 설명하는 선택 필드

한 레코드에는 하나의 사실만 넣는다. 여러 사실을 한 문장에 결합하지 않는다.

### 6.2 규칙 레코드

규칙 후보는 다음 정보를 갖는다.

- 영구 규칙 ID와 한국어 제목
- 규칙의 목적과 적용 범위
- 규범 수준: `must`, `should`, `may`
- 허용 예문과 금지 예문
- 두 예문에서 유지해야 할 행위자·대상·행동·조건·결과·양태의 수동 검토 불변식
- 잘못된 예문을 고치는 방법
- 언어학적 근거와 출처 ID
- 자동 검사 수준: `deterministic`, `heuristic`, `human`
- 알려진 예외와 공개 질문
- 상태: `candidate`, `experimental`, `accepted`, `deprecated`

Phase 0의 모든 규칙은 `candidate` 상태다.

### 6.3 어휘 레코드

어휘 항목은 표제어, 승인 의미, 품사, 허용 형태, 금지 또는 혼동 표현, 권장 대체어, 예문, 분야, 출처, 상태를 갖는다. 한국어의 활용과 조사 결합을 표제어 자체와 분리한다.

Phase 0에서는 형식 검증용 예시 항목만 제공한다. 승인 어휘 목록을 주장하지 않는다.

### 6.4 코퍼스 출처 레코드

코퍼스 후보는 출처명, 제공 기관, 분야, URL, 문서 형식, 예상 규모, 접근 방식, 저작권 표시, 재배포 가능 여부, 파생 데이터 허용 여부, 개인정보 위험, 수집 상태를 갖는다.

`redistribution` 값은 `allowed`, `metadata-only`, `permission-required`, `unknown`으로 제한한다. `unknown` 자료는 내려받아 저장소에 넣지 않는다.

## 7. 초기 규칙 후보 영역

Phase 0에서 다음 열 개 영역을 최소 한 개의 규칙 후보로 만든다.

1. 한 문장에 하나의 작업만 지시한다.
2. 절차문에서 행위 주체 또는 대상이 생략돼 모호해지는 것을 제한한다.
3. 피동 표현은 안전 책임이나 행위자가 흐려지지 않을 때만 사용한다.
4. 조건을 결과보다 먼저 제시한다.
5. 하나의 조건문에 독립 조건을 과도하게 결합하지 않는다.
6. 중첩 관형절과 긴 명사 수식을 제한한다.
7. 동일 개념에는 동일 용어를 사용한다.
8. 대명사와 지시어는 지시 대상이 하나일 때만 사용한다.
9. 문서 유형별 종결 표현을 일관되게 사용한다.
10. 안전 경고에서 위험, 결과, 회피 행동을 분리해 명시한다.

숫자 임곗값은 선행 연구나 파일럿 코퍼스 증거 없이 확정하지 않는다. 문장 길이와 수식 길이는 측정 후보로만 기록한다.

## 8. 작업 흐름

```text
외부 자료 발견
    ↓
서지정보 및 이용 조건 기록
    ↓
원문 확인 가능 여부 판정
    ↓
주장 단위로 근거 연결
    ↓
언어별 비교 또는 한국어 규칙 후보에 반영
    ↓
스키마·링크·완료 조건 자동 검증
```

연구자는 사실 레코드와 KSTL 설계 제안을 분리한다. 외부 언어의 규칙을 발견했다고 해서 한국어 규칙으로 자동 채택하지 않는다. 한국어 규칙 후보에는 한국어 문법 근거와 실제 예문이 모두 필요하다.

## 9. 오류와 불확실성 처리

- 원문을 확보하지 못한 자료는 서지정보와 검색 경로만 기록하고 `secondary` 또는 `unverified`로 둔다.
- 출처가 충돌하면 최신 자료를 자동 우선하지 않는다. 발행 주체, 자료 유형, 적용 판본을 비교하고 충돌 내용을 기록한다.
- 저작권 상태를 판정할 수 없으면 메타데이터만 저장한다.
- 자동 검사가 의미 판단을 요구하면 억지로 정규식 규칙을 만들지 않고 `human`으로 분류한다.
- 스키마 변경으로 기존 데이터가 깨지면 데이터와 스키마를 같은 변경 단위에서 수정한다.
- 잘못된 인수인계 주장은 삭제만 하지 않고 정정 사유와 더 강한 출처를 기록한다.

## 10. 검증 전략

### 자동 검증

- 모든 YAML 파일이 파싱되는지 검사한다.
- 규칙, 어휘, 코퍼스 예시가 대응하는 JSON Schema를 통과하는지 검사한다.
- ID가 중복되지 않는지 검사한다.
- 규칙이 참조하는 출처 ID가 참고문헌에 존재하는지 검사한다.
- Markdown 내부 상대 링크의 대상 파일이 존재하는지 검사한다.
- 저장소에 PDF, 워드프로세서 파일, 원문 아카이브가 실수로 포함되지 않았는지 검사한다.

### 수동 검토

- `verified` 주장마다 실제 원문이 해당 내용을 직접 뒷받침하는지 확인한다.
- 규칙 후보의 허용·금지 예문이 동일한 의미를 전달하는지 확인한다.
- 코퍼스 후보의 이용 조건을 해당 기관의 원문 정책에서 확인한다.
- 언어별 비교표가 공개적으로 확인할 수 없는 수치를 확정값으로 제시하지 않는지 확인한다.

## 11. 라이선스와 명칭

코드는 Apache-2.0을 기본 후보로 한다. 프로젝트가 직접 작성한 문서와 데이터에는 CC BY 4.0을 기본 후보로 하되, 저장소 공개 전에 기여 방식과 데이터 재사용 요구를 검토해 확정한다.

`ASD-STE100`과 `STE`는 출처를 설명하는 데만 사용한다. KSTL이 ASD 또는 STEMG의 인증, 승인, 제휴를 받았다고 표현하지 않는다. 공식 ASD 문서의 로고, 사전, 규칙 전문을 복제하지 않는다.

프로젝트 이름 `KSTL`도 Phase 0에서는 가칭이다. 공개 발표나 패키지 배포 전에 동일 분야 상표와 패키지 이름을 확인한다.

## 12. 근거가 확인된 출발점

- ASD/STEMG 공식 사이트는 Issue 9의 발행일을 2025년 1월 15일로 밝히며, 53개 규칙과 약 900개 승인 단어 구조를 설명한다: <https://www.asd-ste100.org/about_STE.html>
- 공식 다운로드 페이지는 Issue 9 사본을 무료로 요청할 수 있다고 안내한다: <https://www.asd-ste100.org/STE_downloads.html>
- STEMG 공식 도구 안내는 체커가 작성자를 대체하지 않으며 사람의 판단이 필요하다고 명시한다: <https://www.asd-ste100.org/STEsoftware.html>
- Hong과 Kim의 2008년 논문은 한국어-영어 기계번역을 위한 Controlled Korean 설계와 평가를 다룬다: <https://aclanthology.org/Y08-1040/>
- Gobbi의 박사논문 저장소 사본에는 Español Técnico Simplificado 가이드 초안의 규칙부와 사전부가 포함된다: <https://amsdottorato.unibo.it/id/eprint/6681/>
- COM&TEC의 공식 ITS 사이트는 Italiano Tecnico Semplificato를 통제된 자연어 프로젝트로 소개한다: <https://www.italianotecnicosemplificato.it/>

## 13. 이후 단계

Phase 0 완료 후 별도 설계를 거쳐 첫 번째 수직 절편을 만든다. 권장 절편은 규칙·어휘 데이터 로더, 결정론적으로 검사할 수 있는 규칙 3개, JSON 출력이 가능한 CLI, 단위 테스트다. MCP와 LSP는 CLI 규칙 엔진의 인터페이스가 안정된 뒤 추가한다.

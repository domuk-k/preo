# KSTL 규칙 후보 작성 템플릿

이 템플릿은 KSTL 제안 작업 공간에서 규칙 **후보**를 기술하는 형식이다. 후보는
발행된 표준이나 검증된 지침이 아니다. 채택 여부와 규범 강도는 코퍼스 근거,
한국어 전문가 검토, 독해·과업 평가를 거친 뒤 별도로 결정한다.

## 필드

- `id`: `KSTL-`과 세 글자 범주, 세 자리 번호로 이루어진 안정 식별자이다.
- `title`: 작성자가 바꿀 언어적 특성을 짧게 쓴다.
- `purpose`: 왜 이 항목을 후보로 검토하는지 쓴다. 출처가 입증한 범위와 아직
  검증하지 않은 효과를 구분하며, 가독성이나 안전성 효과를 단정하지 않는다.
- `scope`: 후보를 적용해 볼 문서 기능이다. `procedure`, `description`,
  `warning`, `all` 가운데 하나 이상을 쓴다.
- `normativity`: 채택될 경우의 제안 강도인 `must`, `should`, `may` 중 하나이다.
  `status: candidate`일 때는 현재의 표준 의무를 뜻하지 않는다.
- `status`: Phase 0의 규칙에는 `candidate`를 쓴다. 이는 검토할 가설이라는
  뜻이며 승인 상태가 아니다.
- `automation`: 검사 방식의 상한을 쓴다. `deterministic`은 용어표나 문체처럼
  먼저 설정된 값과의 정확한 불일치를 찾을 수 있다는 뜻이다. `heuristic`은
  형태 단서로 검토 대상을 표시할 수 있을 뿐 위반을 판정할 수 없다는 뜻이다.
  `human`은 의미와 문맥 판단이 핵심이어서 사람이 판정해야 한다는 뜻이다.
- `approved_examples`: 후보 요구를 만족하도록 쓴 자연스러운 한국어 예이다.
- `unapproved_examples`: 같은 행위자, 행동, 조건, 결과, 양태, 부정, 위험 정보를
  유지하면서 후보 요구만 어긴 자연스러운 한국어 예이다. 짝을 고칠 때 원문에
  없던 사실을 추가하지 않는다.
- `example_invariants`: 허용·비허용 예문 쌍에서 동일하게 유지한 행위자, 대상,
  행동, 조건, 결과, 순서, 양태와 작성자 의도를 사람이 대조해 기록한다. 이 필드는
  수동 의미 검토의 감사 기록이며 자동 검사가 의미 동일성을 증명한다는 뜻이 아니다.
- `rewrite_guidance`: 작성자가 무엇을 어떻게 바꾸는지, 자동 검사가 있다면 그
  결과를 어떻게 검토하는지 구체적으로 쓴다.
- `source_ids`: `research/bibliography.md`의 식별자만 쓴다. 출처는 후보의
  이론적·실험적 동기를 직접 뒷받침해야 하며, 인용만으로 후보 효과가 입증되지는
  않는다.
- `exceptions`: 적용하지 않을 구체적 문맥을 하나 이상 쓴다.
- `open_questions`: 대상 코퍼스나 측정 방법을 포함한 반증 가능한 연구 질문을
  하나 이상 쓴다.

## 언어 요구와 검사기 신호

언어 요구는 작성자가 최종 문장에서 만족시켜야 할 의미·형식 조건이다. 검사기
신호는 그 요구를 어겼을 가능성을 알려 주는 관찰값일 뿐이다. 예를 들어 조건절
뒤에 주절이 있는지는 형태 분석으로 표시할 수 있지만, 그 절이 실제 조건인지와
순서 변경이 뜻을 보존하는지는 작성자가 확인해야 한다. 따라서 `heuristic` 경고를
규칙 위반으로 자동 확정해서는 안 된다.

## 완전한 YAML 예

```yaml
- id: KSTL-SYN-001
  title: 조건을 결과보다 먼저 쓴다
  purpose: >-
    조건 표현의 위치를 비교 평가하기 위한 후보이다. im-nam-2009는 특정한
    과거 번역 경로에서 조건 부사어를 연구했지만, 이 어순의 일반적 효과를
    입증하지는 않았다.
  scope: [procedure, description]
  normativity: should
  status: candidate
  automation: heuristic
  approved_examples:
    - 온도가 80 °C를 넘으면 경고등이 켜집니다.
  unapproved_examples:
    - 경고등이 켜지는 조건은 온도가 80 °C를 넘는 경우입니다.
  example_invariants:
    - 두 예문 모두 온도가 80 °C를 넘는 조건에서 경고등이 켜진다는 같은 조건-결과 관계를 진술한다.
  rewrite_guidance: >-
    결과절의 조건을 확인하고 그 조건절을 결과절 앞에 옮긴다. 검사기는 후행
    조건 표지를 검토 대상으로 표시할 수 있지만 조건의 의미와 적용 범위는
    작성자가 확인한다.
  source_ids: [im-nam-2009]
  exceptions:
    - 결과가 표의 열 제목이고 적용 조건이 바로 아래 셀에 명시된 형식은 문서 구조로 검토한다.
  open_questions:
    - 절차문 코퍼스에서 조건 선행형이 후행형보다 조건 적용 판단의 정답률을 높이는가?
```

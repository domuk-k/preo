# sulsul 외부 문서 파일럿 기록 (2026-08)

공개 한국어 개발자 문서에 sulsul v0 규칙을 적용한 규칙 히트 통계다.
원문 문장은 이 저장소에 옮겨 적지 않는다. 원문은 각 URL에서 확인한다.

## 판정 방법

두 문서 모두 WebFetch로 본문 전체를 작업 메모리로만 가져와 산문 문장을
전수 검사했다(표본 추출 없음). 문장 판정 기준은
`skill/sulsul/references/rules.md`의 규칙 16개 전부다. 코드 블록, 표
셀, 헤더, 서술어 없는 목록 레이블/링크는 문장 수 집계와 판정 대상에서
제외했다. 게이트 규칙(KSTL-SYN-002, KSTL-REF-001, KSTL-SAF-001)은
내부 dogfood와 동일한 기준으로, 표면적으로 생략 논항·대명사가
등장하더라도 문맥상 후보가 하나뿐이면(규칙 자체의 예외 조항) 히트로
세지 않고, 진짜 다중 후보 모호성이 있을 때만 게이트 발동으로 센다.

  명시하지 않아 경계 사례로 남긴다.

## 종합 관찰

- 내부 dogfood(docs/pilot/2026-08-sulsul-dogfood.md)와 비교한 규칙 히트
  분포 차이: 내부 dogfood는 문장 59개에 히트 2건(히트율 약 3.4%,
  TER-001과 EXP-002 각 1건)이었다. 외부 파일럿은 문장 143개(82+61)에
  히트 12건(히트율 약 8.4%)으로 더 높았고 규칙 종류도 더 다양했다
  (MOD-001, DOC-001, STY-001, EXP-003, EXP-005, EXP-006이 이번에
  처음 히트를 냈다). 가장 큰 차이는 DOC-001이다: 내부 dogfood는
  대상 문서가 전부 설명문이라 이 규칙이 구조적으로 적용될 문장 자체가
  없었는데, React 튜토리얼처럼 절차문이 있는 외부 문서에서는 처음으로
  히트(및 오탐 경계 사례)를 관찰했다. 이는 브리핑에서 예상한 대로
  "절차 스코프 규칙은 외부 튜토리얼 문서에서만 검증된다"는 가설을
  뒷받침한다. 반면 질문 게이트 규칙(SYN-002, REF-001)은 내부·외부
  두 라운드 모두에서 한 번도 진짜로 발동하지 않았다 — 표본 문서 두
  종류(공식 설명문, 공식 튜토리얼) 모두 대체로 잘 편집되어 생략 논항과
  지시어의 지시 대상이 항상 하나로 좁혀졌기 때문으로 보인다. 이 두
  규칙의 게이트 UX는 여전히 리허설되지 못했으며, 다음 라운드는 AI가
  초안으로 막 작성한 절차문이나 편집이 덜 된 커뮤니티 위키 문서를
  대상으로 삼아야 게이트가 실제로 발동하는 사례를 관찰할 가능성이
  높다.
- 규칙 후보 조정이 필요해 보이는 항목:
  - KSTL-EXP-002: 규칙 본문이 "~에 대하여"·"~에 대한" 두 형태만
    명시한다. 실제 문서에는 축약형 "~에 대해"도 같은 번역투 문제로
    나타난다(문서 2에서 관찰). 검사기 구현 시 이 축약형을 포함할지
    candidates.yaml 단계에서 명시하면 좋겠다.
  - KSTL-EXP-006: 규칙 제목은 "~의 경우"(명사+의)만 가리키는 것처럼
    읽히지만 규칙 자체의 비승인 예문("만료된 경우")은 동사 활용형
    +"경우"도 포함한다. 문서 2에서 나온 히트 3건이 모두 동사 활용형
    쪽이었다. 적용 범위가 이미 넓다는 걸 확인했으니 제목 표현만 다듬어
    오해를 줄이면 좋겠다.
  - KSTL-DOC-001: "분리할 수 없는 하나의 조작" 예외가 튜토리얼
    문서에서 실제로 걸린다(예: 함수 호출과 인자 전달을 한 문장으로
    쓰는 경우). 형태 분석만으로는 두 동사가 "독립된 단계"인지 "하나의
    API 호출"인지 구분할 수 없으므로, 검사기가 표시만 하고 최종
    판단은 작성자가 하도록 하는 현재 설계가 맞다는 것을 이번 표본이
    재확인했다. 규칙 문서 자체를 바꿀 필요는 없어 보인다.
  - KSTL-STY-001: 튜토리얼 장르에서 "~해야 합니다"(필요성 서술)와
    "~하세요"(직접 명령)를 같은 procedure 기능 안에서 의도적으로 섞어
    쓰는 관행이 관찰됐다. 규칙이 이 두 화행을 같은 "procedure" 범위로
    묶어 처리할지, 세분화할지는 후속 파일럿에서 튜토리얼 성격 문서를
    더 모아 판단할 필요가 있다.
  - KSTL-MOD-001: 내부 dogfood에서는 후보가 전혀 없어 정탐 사례를
    검증하지 못했는데, 이번에 공식 문서에서 정탐 후보를 처음
    확보했다. 규칙 표현을 바꿀 필요는 보이지 않는다.
